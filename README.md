# Portfolio

Static site, no build step. Two pages — `index.html` (about) and
`projects.html` — that read all their content at runtime from two plain-text
files in this folder:

| File | What's in it |
| --- | --- |
| `info.txt` | Everything personal: name, contact, about, skills, experience, projects. **This is the file you edit.** |
| `AIDisclaimer.txt` | The AI statement, rendered verbatim. Edit it like any text file. |
| `projects/*.txt` | One project per file. Every one is loaded automatically. |
| `projects/index.txt` | Generated. The list of project files — see below. Don't hand-edit. |

You should not need to touch the HTML at all.

## Running it locally

The pages fetch those two `.txt` files, which browsers block on `file://`
pages. Serve the folder instead:

```sh
python3 -m http.server 8000
```

then open <http://localhost:8000>. Opening `index.html` by double-clicking
shows a red banner explaining the same thing. GitHub Pages serves over http,
so the deployed site is unaffected: push to `main` and enable Pages on the
repo root.

## Editing `info.txt`

The format is `key = value`, one per line, grouped under `[section]` headers.
Lines starting with `#` are comments. A line of `---` separates repeated
entries. The file itself documents every field.

- **Plain-list sections** (`[awards]`, `[affiliations]`) take one item per
  line; a leading `- ` is optional. `[education]` and `[experience]` share the
  same `when / role / org / detail` shape.
- **Add a project** — `cp projects/_template.txt projects/my-thing.txt`,
  fill it in, done. Every `.txt` in `projects/` is picked up automatically.
  Files starting with `_` are ignored, so `_template.txt` never shows and you
  can park a draft as `_draft-thing.txt`. A copy you haven't filled in yet is
  skipped too (it logs which ones to the console), so an untouched template
  never appears as a blank card. A line that isn't `key = value` continues the
  field above it, so descriptions can wrap across as many lines as you like.
- **Hide something** — leave its value empty. Empty contact links are dropped;
  a section with no entries hides itself.
- **`note`** puts a bordered callout on a card. It's meant for proprietary
  projects, to say what you *can* say.

## The AI statement

`AIDisclaimer.txt` is rendered as written, with two conventions:

- Everything before a line reading exactly `In-depth explanation:` shows
  immediately; everything after goes behind an expandable toggle, so the modal
  stays readable.
- In the first part, a line shaped `Short Label: sentence` renders as a
  numbered tenet. An ALL-CAPS lead-in (like `NOTE:`) stays ordinary prose.

Change the wording freely — if a line stops matching those shapes it just
renders as a paragraph. The one-line summary in the banner and the modal
heading come from `[ai]` in `info.txt`.

The modal auto-opens once per visitor on the homepage (`localStorage` key
`ai-philosophy-seen`); the banner button and footer link reopen it on any
page. `data-auto-popup` on `<body>` controls the auto-open.

**Ctrl+Alt+D** clears that flag so the first-visit popup can be tested again.
On the homepage it reloads straight into the popup; elsewhere it just confirms
and the popup shows next time you land on the homepage. The flag is per
browser, so this only resets your own copy.

Tabs are linkable: `projects.html#in-progress`, `#future`, `#proprietary`.
Defaults to `#finished`.

## Project images

Optional. Drop an image next to a project's `.txt` with the **same base name**
and any common extension — `projects/homelab.txt` picks up
`projects/homelab.png`, `.jpg`, `.jpeg`, `.webp`, `.avif`, `.gif` or `.svg`.
Nothing to configure; the card looks for them in that order and uses the first
that loads. To point somewhere else, set `image = path/to/pic.jpg` in the
project file. A project with no image just renders as a plain card.

## The "Small Stuff" tab

The fifth tab on the projects page is a plain bullet list — no cards, no
hardware/software split. Edit it under `[small_stuff]` in `info.txt`, one
bullet per line (a leading `- ` is optional). It's the place for one-off
repairs, scripts, and small fixes that don't warrant a project file.

## How projects are discovered

GitHub Pages serves no directory listings, so a browser can't ask what's in
`projects/`. The site works around that with three fallbacks, in order:

1. **`projects/index.txt`** — a generated manifest. This is what works on
   Pages. It's regenerated by `./make-index.sh`, and the GitHub Action in
   `.github/workflows/project-index.yml` runs that on every push — so in
   practice you add a `.txt`, push, and it appears.
2. **A directory listing of `projects/`** — what `python3 -m http.server`
   returns. Means new files show up locally with no regeneration at all.
3. **`[project_files]` in `info.txt`** — a manual override, normally empty.

If you'd rather not have the Action, delete the workflow file and run
`./make-index.sh` yourself before pushing. Order within a subcategory is
alphabetical by filename.
